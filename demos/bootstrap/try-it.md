- Open **Visitor log** and sign in. The greeting word, "Welcome", came from the configuration the bootstrap installed the app with.
- Under **How the bootstrap set up this pico**, the installed rulesets are in install order: the bootstrap, then `io.picolabs.xmlui`, then `com.example.visitors.format` (a module), then `com.example.visitors`, which uses it. Open the child pico's **Logging** tab to follow the chain of `wrangler:ruleset_installed` events that drove each step.
- Under **This app's channel**, the policy lists the events of the app's documented rules. It doesn't list `wrangler:ruleset_installed`, which its install rule selects, or the event only `set_up_channel` raises.
- Click **Run the channel rule again**: the same channel is updated, and its id doesn't change. Click **Make a duplicate, the naive way** twice: three channels with the same tags. Click **Clean up duplicates**: only the channel this page uses is left.
- Add a documented rule to `com.example.visitors.krl` that selects `visitor waved`, and click **Flush**. Sending `visitor/waved` on the page's channel is refused: flushing doesn't run install rules again. Click **Run the channel rule again** and send it again. Now it works.
