# Pico Engine 1.6 — Release notes

**Status:** Ready for release (version bump and npm publish follow commit)  
**Audience:** Pico Labs team, Confluence paste, external release announcement draft

---

## Highlights

Pico Engine **1.6** adds **Layer 2 identity and subscriptions**: every pico has a portable **did:webvh**, subscriptions can be formed with **DIDs** instead of well-known ECIs, and picos on **different engines** can subscribe and exchange queries/events over **SKY + DIDComm**.

Passkeys, OAuth (1.5), and **legacy ECI subscriptions** continue to work unchanged.

---

## New capabilities

### Identity (did:webvh)

- Each pico receives a **did:webvh** at creation, served at `/picos/{picoId}/did.jsonl`.
- **`PICO_ENGINE_BASE_URL`** is embedded in the DID document; must be stable and peer-reachable for cross-engine use.
- Root picos default **`publicIntro: true`** (accept unsolicited Layer 2 intro); child picos default **`false`**.

### Layer 2 subscriptions

Use the right identifier when creating a subscription:

| Field | Layer 2 | Legacy |
|-------|---------|--------|
| **`target_did`** | Recipient's **did:webvh** (`wrangler:myDid`, Identity panel) | *Do not use* |
| **`wellKnown_Tx`** | *Do not use* | Recipient's **wellKnown_Rx ECI** |
| **`name`** | Human label on the subscription bus | Same |
| **Peer DID (`did:peer:…`)** | *Not at create time* — minted during SKY intro | N/A |

- Initiate with `wrangler:subscription` and **`layer2: true`**, **`target_did`** = recipient's **did:webvh** (not peer DID, not wellKnown ECI).
- After SKY intro handshake, subscription stores **`Tx_did`** / **`Rx_did`** (did:peer) instead of remote Tx/Rx ECIs.
- **Same engine:** intra-mesh traffic uses verified local dispatch when appropriate.
- **Cross-engine:** intro, response, queries, and events use DIDComm to the peer's ingress URL.

### Developer UI

- **Subscriptions** tab: identity (`myDid`, `publicIntro`), Layer 2 create, inbound approval, established/outbound lists with **subscription name**, test send, inline Rx policy editing.
- **Channels** tab: optional custom **channel id (ECI)** at creation; **`?focus=<eci>`** deep link.
- **Forest view:** movable **Off Engine** sink for cross-engine subscriptions; pico positions **persist across engine restart**.
- **Passkeys:** credential labels include **`host:port`** when running multiple engines on one machine.

### Dependencies

- Requires **pico-framework `^0.8.1`** (custom channel id at creation, `eciIsTaken`). Publish framework before engine.

### Wrangler / KRL

| API | Notes |
|-----|-------|
| `wrangler:myDid()` | Caller's did:webvh |
| `wrangler:publicIntro()` / `set_public_intro` | Public intro toggle |
| `wrangler:picoQuery(eci, …)` | `eci` may be did:webvh or did:peer |
| `event:send({ did: … })` | Event to remote pico by DID |
| Legacy `wrangler:subscription` + `wellKnown_Tx` | Unchanged |

## Breaking changes and migration

| Change | Action |
|--------|--------|
| **New Layer 2 subs need 1.6 peer** | Both sides must run 1.6+ for `layer2: true` / `target_did` flow |
| **Legacy subs unchanged** | Existing ECI-based subscriptions keep working; no automatic migration |
| **`io.picolabs.did-o` deprecated** | Remove from rulesets; use `wrangler:picoQuery` + `event:send` with DIDs |
| **`dido:prepareQuery` deprecated** | Same replacement |
| **Stable base URL** | Set `PICO_ENGINE_BASE_URL` before creating picos you will use cross-engine; DIDs embed this URL |

## Cross-engine demo (two processes on one machine)

```sh
# terminal 1 (repo root)
PICO_ENGINE_HOME=/tmp/pico-engine-a PORT=3001 npm start

# terminal 2
PICO_ENGINE_HOME=/tmp/pico-engine-b PORT=3002 npm start
```

| Instance | URL | Data |
|----------|-----|------|
| Engine A | http://localhost:3001 | `/tmp/pico-engine-a` |
| Engine B | http://localhost:3002 | `/tmp/pico-engine-b` |

Default `PICO_ENGINE_BASE_URL` (`http://localhost:$PORT`) works for passkeys and peer DID fetch.

**Demo steps:**

1. Register passkey on both UIs.
2. On B: query `wrangler:myDid` → copy did:webvh.
3. On A: Subscriptions → Layer 2 create → paste B's DID → submit.
4. On B: approve inbound subscription.
5. On A: test query or event to B.

Full troubleshooting: [`docs/guides/layer2-subscriptions.md`](../guides/layer2-subscriptions.md).

## Deferred (not in 1.6)

- Legacy subscription **migration** to Layer 2 (new subs only)
- **Pico move** / did:webvh rotation ([pico-move.md](../design/pico-move.md))
- **VC-based authorization**
- **did:peer:4** (1.6 uses num_algo 2)
- Retire **`dido.ts`** (deprecated in 1.6, removal planned 1.7+)
