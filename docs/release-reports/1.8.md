## Highlights

1. **Pico schemas.** `/** */` doc annotations on rules and shared functions become a schema; `wrangler:picoSchema`, `rulesetSchema`, and `channelSchema` expose it, and `krl-check` lints it.
2. **Channel policy fixed.** Deny now overrides permit. Parents can set a policy ceiling on children, operators can set global deny lists, and an opt-in setting requires a validated bearer on wildcard `/sky/*`.
3. **MCP, two ways.** A dev stdio server (`pico-engine mcp --stdio`) for local agents, and mesh Streamable HTTP at `/mcp/:eci` with an OAuth bearer.
4. **Operator config file.** `~/.config/pico-engine/config.json`, `pico-engine -c`, `PICO_ENGINE_CONFIG`.
5. **Install and flush tell you what failed.** `ctx:validate` runs before install and flush; rule outcomes (fired, not fired, not selected) come back on event-wait responses.

## Why it matters

- **A pico can describe itself.** Schemas are what let an agent, the Testing tab, or Home Assistant call a pico without reading its KRL. 1.10's MCP work stands on this.
- **Policy now means what it says.** Before 1.8, a permit could override an explicit deny. That was a long-standing correctness bug in the authorization gate.
- **Agents in the dev loop.** With `krl-check` and the dev MCP server, an agent can validate, install, raise, and query without a human copying code around.

## Exposure before → after

| Surface | 1.7 | 1.8 |
|---|---|---|
| Channel policy conflict | Permit could win over an explicit deny | Deny overrides permit (pico-framework 0.8.2) |
| Child channel policies | Any policy the child sets | Capped by the parent's policy ceiling; optional `defaultRootPolicyCeiling` |
| Engine-wide blocks | None | `globalEventDeny` / `globalQueryDeny` in config |
| Wildcard `/sky/*` channels | Open | Unchanged by default; `wildcardSkyRequireBearer` opt-in |
| Agent access | None | `/mcp/:eci` with OAuth bearer |
| Default root UI channel | Permissive for the owner | Unchanged (documented as permissive) |

## Upgrade

- Requires pico-framework `^0.8.2`.
- Environment variables still work, but the config file wins over `PORT` and `PICO_ENGINE_HOME` when both are set.
- Rulesets that relied on permit beating deny will see calls refused.
