# Pico Engine 1.7.0 — Release notes

**Status:** October 10, 2026  
**Requires:** pico-framework `^0.8.1` (unchanged from 1.6.x)

---

## Highlights

**Identity portability** — Layer 2 relationships formed on 1.7+ use **did:peer:4** (existing peer:2 subs unchanged).

**Portable subtree move** — Export and import a pico subtree (rulesets, entity state, channels, schedules, identity snapshots) with **`io.picolabs.portable_subtree`**, **`IdentityService.exportPortableSubtree()` / `importPortableSubtree()`**, and DID rotation so cross-engine Layer 2 relationships survive relocation.

**Ruleset state portability** — **`ctx:exportRulesetState` / `ctx:importRulesetState`** for encrypted single-ruleset blobs.

**Developer UI** — Rulesets **flush** reinstalls an already-installed RID on that pico (so flushed KRL takes effect without a separate Install click).

---

## Operator notes

### Portable move (two engines)

See **`docker-compose.cross-engine.yml`** and **`docs/design/pico-move.md`**. Donor mesh exports via Manifold portable-thing flow; recipient mesh imports under a Manifold parent. Importer must provide platform services the subtree relied on in the donor mesh (e.g. Manifold app under a Manifold parent).

### Manifold KRL

Manifold application rulesets live in **[manifold-api](https://github.com/Picolab/manifold-api)**. After upgrading the engine, **flush** (and now auto-**reinstall** on flush) **`io.picolabs.manifold_pico`** on each Manifold app pico, not only on the mesh root.

### Docker

```bash
docker build -f Dockerfile.local \
  --build-context pico-framework=../pico-framework \
  -t picolabs/pico-engine:1.7.0 .
```

## Breaking / migration

- **New** Layer 2 subscriptions on 1.7+ use did:peer:4.
- **Existing** peer:2 Layer 2 subscriptions unchanged.
- Legacy **`io.picolabs.did-o`** is not part of 1.7 portable move paths.
