## Follow-up (post club gear demo)

The gitignored **`demos/io.picolabs.club_gear_demo.krl`** Manifold setup exposed a scheduler footgun: **`schedule … at time:add(…, {"seconds": expr})` does not evaluate KRL variables in the map** — the delay can silently become **`time:0`**, which re-queues the event immediately and can hang the engine in a tight loop.

**Design rule:** prefer **callbacks over scheduling** for multi-step setup — Manifold
`callback_eci` + `rcn` and completion events (`community:thing_completed`,
`community:community_completed`) are deterministic; timers are not. See `MEMORY.md` § "Prefer
callbacks over scheduling".

**Until fixed in the engine**, demo rulesets must use **literal** second counts in `time:add` (e.g. `{"seconds": 4}`), not globals or function results — or avoid schedules entirely when a callback exists.

**Same-pico query deadlock:** `ctx:query(…, "io.picolabs.manifold_pico", "getThings")` (or `getCommunities`) **from an event handler on that same Manifold pico** can hang forever — the cleanup event holds the transaction while the query waits on itself. Demo cleanup must use **entity vars** (`ent:cleanup_bike_id`, `ent:cleanup_community_id`) captured when subscriptions are established, not live Manifold queries.

**Engine change (TODO, after demo is stable):** reject or warn on scheduled events with **`time <= now`** (or `time == 0` relative to queue semantics) at schedule time, so accidental zero-delay loops fail fast instead of freezing the pico.

**Hang postmortem (Oct 2026):** [`docs/design/engine-hang-postmortem-2026-10.md`](../design/engine-hang-postmortem-2026-10.md) — episodes, UI as canary, open resilience work.
