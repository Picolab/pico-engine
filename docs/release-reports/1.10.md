## Highlights

1. **Agents can connect safely.** An MCP client discovers the engine, gets an OAuth token (PKCE S256, RFC 8707 resource binding), and a person approves it with a passkey.
2. **Channels are hidden from MCP by default.** A channel's `mcpPolicy` has to allow the `channel` or `mesh` surface, and its event and query policies still decide each call.
3. **`/c/` is internal.** A proxied request, or a remote `Host: localhost` header, is no longer a local caller.
4. **Secrets stay out of KRL.** Credential headers are stripped from `_headers`, secret PDS settings are masked, and webhooks get `math:timing_safe_equal` and `event:raw_body()`.
5. **pico-framework moved into the monorepo** at `packages/pico-framework` and is versioned with the engine. `Picolab/pico-framework` is archived.

## Why it matters

- **Agents become first-class callers without becoming insiders.** The path an agent uses (`/mcp/…`) is separate from the internal API (`/c/`) and from credentials, so an agent's reach is exactly the channels a person exposed.
- **Default deny means upgrades don't widen exposure.** Nothing existing is visible to MCP until someone opts a channel in.
- **One release train.** With pico-framework in the repo, a framework fix no longer needs a separate publish and a dependency bump.

## Exposure before → after

| Surface | 1.9.5 | 1.10 |
|---|---|---|
| `/c/` internal API | Reachable through a proxy on the same host | 401 unless passkey session, internal token, or opt-in direct loopback (`PICO_ENGINE_ALLOW_LOCALHOST_C=1`) |
| External `/sky/*` | Open unless the channel required a bearer | Bearer required once `io.picolabs.oauth` is on the root; exempt: tagged `mesh-oauth-exempt`, `didcomm` and `ingress` |
| MCP on channels | Bearer token, no per-channel opt-in | OAuth with resource binding and scopes, plus `mcpPolicy`, default deny |
| `_headers` in KRL | Included `Authorization`, `Cookie` | `Authorization`, `Proxy-Authorization`, `Cookie`, `X-Pico-Internal` removed |
| Session cookies | Visible in `_headers` | `http:cookie(name)` never returns `pico-session` or `pico-ceremony` |
| Secret PDS settings | Readable by other rulesets | `{ "secret": true, "set": true }`; only the owning ruleset reads the value |
| Public-client tokens | — | 1-hour access token; refresh rotates; replaying an old refresh token revokes the grant |

## Upgrade (breaking)

- `/c/` behind nginx or from another host returns 401.
- Install `io.picolabs.oauth` on the root before a remote MCP client signs in. Claude needs a public HTTPS URL on port 443.
- Existing channels are not exposed to MCP until the `channel` or `mesh` surface is allowed in the Channels tab.
- `settings` no longer returns secret values to other rulesets.
- Public MCP clients must store the new refresh token from each refresh.

Also: flush `io.picolabs.pds` and `io.picolabs.pico-engine-ui` after upgrade. Node 20 or 22.

## Patch release

**1.10.1** (same day). 1.10.0 recompiled every cached ruleset at startup (the cache directory includes the compiler version), and concurrent writes left half-written modules: `Compiled ruleset is missing init`. Each file is now compiled once, written to a temp file, and renamed into place. Two engines on one `PICO_ENGINE_HOME` can still race.
