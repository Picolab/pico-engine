## Highlights

1. **Logging tab.** A per-pico in-memory ring (default 200 entries) of events, queries, rules, policy decisions, entity writes, sends, and directives, with a two-pane inspector, live stream, and filters.
2. **XMLUI views served by the engine.** A shared function tagged `@view` is a page at `/ui/{eci}/{rid}/`; 1.9.4 added `@component` for reusable pieces and shared theme and settings components.
3. **Try It! tab and cookbook.** Eleven runnable demos (Thermostat, Echo, Score tracker, KBlog, and others), each a single bootstrap ruleset with a README and a cookbook page.
4. **Docs moved home.** The KRL manual and developer docs left Confluence for the repo's Docsify site at docs.picolabs.io.
5. **Flush runs the new code.** Before 1.9.4, a pico could run one flush behind until a restart because of a 100 ms ruleset cache.

## Why it matters

- **Debugging without the log file.** Developers (and agents using MCP) can see why a rule fired or didn't, and which policy blocked a call, from the pico itself.
- **Picos carry their own UI.** A ruleset can ship its views; no separate front-end project is needed for small apps.
- **Learning by running.** The demos turn the cookbook from text into something a newcomer can flush and edit.

## What's now visible

| Question | Before 1.9 | 1.9 |
|---|---|---|
| Which rules fired for this event? | `pico-engine.log`, all picos mixed | Logging tab, per pico, with rule names |
| Why was a call refused? | The error returned to the caller | Policy decision logged with the transaction |
| What did the pico write? | Inspect entity state after the fact | Entity writes in the transaction |
| Same-engine `ctx:query` | Separate entries | Nested under the caller |

## Upgrade

- Requires krl-compiler `^1.6.1`. Older compiled rulesets still run; rule names appear after a recompile or flush.
- Flush `io.picolabs.pico-engine-ui` so `logs()` returns the transaction list.
- Flush `io.picolabs.xmlui` to move a pico's views to XMLUI runtime 0.14.28 (1.9.2).
- The Logging tab reads an in-memory ring; a restart clears it.
