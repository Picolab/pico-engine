# Pico Engine 1.6.4 — Release notes

**Status:** September 15, 2026  
**Requires:** pico-framework `^0.8.1` (unchanged from 1.6.x)

---

## Highlights

**Mesh OAuth + LoRa ingress:** tag a channel **`mesh-oauth-exempt`** to allow unauthenticated `/sky/event/...` POSTs (Helium, ChirpStack) while **`io.picolabs.oauth`** stays on the root for Home Assistant and other integrators.

**Rulesets tab:** browse bundled engine KRL from **`packages/pico-engine/krl/`** and install with one click; already-installed rulesets are hidden from the list.

**OAuth safety:** **`io.picolabs.oauth`** can only be installed on the **root pico** (mesh lock marker).

---

## Operator notes

### Mesh OAuth + sensors

When mesh OAuth is enabled:

| Channel need | Tag / setup |
|--------------|-------------|
| LoRa/Helium ingress (no Bearer header) | **`mesh-oauth-exempt`** on the thing's lht65 channel |
| Integrator with Client Credentials | **`oauth-webhook`** + channel secret |
| Home Assistant / ACG | OAuth app in Settings (unchanged) |

Bearer evaluation order: `didcomm`+`ingress` → open; `oauth-webhook` → Bearer required; `mesh-oauth-exempt` → open; root has `io.picolabs.oauth` → Bearer required.

Add **`mesh-oauth-exempt`** on **New Channel** (one-click when mesh lock is on) or **Edit channel → Tags** on existing channels.

### ECS / Docker deploy

After `docker push` with tag **`1.6.4`**, create a **new ECS task definition revision** pointing at `:1.6.4` (not a pinned `@sha256:…` digest), then update the service.

Sanity check after deploy (signed in):

```javascript
fetch('/api/oauth/mesh-enabled', { credentials: 'include' }).then(r => r.json())
```

404 = old image; JSON = 1.6.4+.

Build from checkout:

```bash
docker build -f Dockerfile.local \
  --build-context pico-framework=../pico-framework \
  -t <account>.dkr.ecr.<region>.amazonaws.com/pico-engine:1.6.4 .
```
