## Highlights

1. **Every pico has a did:webvh**, served at `/picos/{picoId}/did.jsonl`.
2. **DID-based relationships.** Form a relationship with a pico's DID instead of a well-known ECI; established relationships use did:peer for traffic.
3. **Cross-engine picos.** Intro, queries, and events between engines go over encrypted DIDComm; same-mesh traffic stays local.
4. **Subscriptions became relationships** (1.6.2) in the UI and wrangler events, with the old `subscription_*` names still accepted.
5. **Mesh OAuth with sensor ingress** (1.6.4). Tag a channel `mesh-oauth-exempt` so LoRa webhooks (Helium, ChirpStack) post without a bearer while the rest of the mesh stays locked.

## Why it matters

- **Identity that isn't an ECI.** ECIs are engine-local handles; a DID is a portable identifier. This is the base for 1.7's moves and for any pico that talks to software outside the engine.
- **Two meshes can relate without sharing an engine.** That's the "Layer 2" in the identity plan: picos as peers across hosts.

## What changed for identity

| | 1.5 | 1.6 |
|---|---|---|
| Pico identifier | ECIs only | did:webvh per pico, plus ECIs |
| Forming a relationship | `wellKnown_Tx` ECI | `target_did` (did:webvh) with `layer2: true`, or the legacy ECI path |
| Cross-engine messaging | `io.picolabs.did-o` | SKY intro + DIDComm; did-o deprecated |
| Unsolicited intros | — | Root picos accept by default (`publicIntro: true`); children don't |
| Self-relationship | Not blocked | Blocked (1.6.3) |

## Upgrade (breaking)

- Both sides need 1.6+ for DID-based relationships. Existing ECI relationships keep working; there's no automatic migration.
- Set `PICO_ENGINE_BASE_URL` before creating picos you'll use across engines; the DID embeds it.
- Remove `io.picolabs.did-o` and `dido:prepareQuery`; use `wrangler:picoQuery` and `event:send` with DIDs.
- Requires pico-framework `^0.8.1`; publish the framework before the engine.
