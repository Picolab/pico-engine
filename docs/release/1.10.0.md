# Pico Engine 1.10.0 — release notes

**Theme:** Secure remote access for agents. An MCP client can discover this engine and obtain a token through OAuth. A person signs in with a passkey and approves that client. The client then uses only the channels that person exposed. The engine's internal API, credentials, and webhook secrets stay off that path.

Design: [`secure-remote-access-1.10.md`](../design/secure-remote-access-1.10.md). Connecting a remote client is [AI tools over MCP](../developing/mcp-ai-tools.md).

## Highlights

- **`/c/` is internal.** A remote `Host: localhost` header, or a request that arrived through a proxy, is not a local caller. The dev MCP sends `X-Pico-Internal` from `$PICO_ENGINE_HOME/internal-token`. `PICO_ENGINE_ALLOW_LOCALHOST_C=1` is the opt-in for a direct loopback connection.
- **MCP authorization.** `/.well-known/oauth-authorization-server` and `/.well-known/oauth-protected-resource/mcp/{eci}` (and `…/mcp/mesh/{eci}`). The authorization server advertises `token_endpoint_auth_methods_supported` of `none` and `client_secret_post`, and `client_id_metadata_document_supported`. The same document is served with the MCP path inserted, and at `/.well-known/openid-configuration`. The issuer is the engine origin. PKCE is S256 only. Tokens record an RFC 8707 `resource`. An https `client_id` is a Client ID Metadata Document. Scopes are `mesh:read` and `mesh:act`.
- **Channel MCP exposure, default deny.** `mcpPolicy` sits beside event and query policy. `/mcp/{eci}` and `/mcp/mesh/{eci}` refuse a channel that did not allow that surface. On a channel endpoint, that channel's event and query policies decide which calls succeed. A mesh endpoint lists the subtree, and the target channel's policies allow or refuse `query` and `raise_event`.
- **Whole-mesh MCP.** `/mcp/mesh/{eci}` tools are `pico_tree`, `pico_channels`, `query`, and `raise_event`. `mesh:admin` is reserved and unlocks nothing.
- **Sign-in.** `io.picolabs.oauth` must be installed on the root before a person can approve an MCP client. The Engine KRL Directory lists that ruleset only on the root. A channel URL and a mesh URL both use that sign-in. Installing the ruleset also makes external `/sky/*` calls require a bearer token, except channels tagged `mesh-oauth-exempt`, or `didcomm` and `ingress`.
- **`pico-framework` is in this repo** at `packages/pico-framework`, versioned with the engine. It moved on November 16, 2026, and `Picolab/pico-framework` is archived.
- **A port already in use** stops startup with `Port N is already in use` and closes the database. The process exits 1.

## Credentials and webhooks

- **Headers.** `Authorization`, `Proxy-Authorization`, `Cookie`, and `X-Pico-Internal` are removed before KRL sees `_headers`.
- **`http:cookie(name)`** reads one application cookie. `pico-session` and `pico-ceremony`, including port-scoped names, are never returned.
- **Secret PDS settings.** `settings` returns `{ "secret": true, "set": true }`. The owning ruleset reads the value with `config_value`, which uses `meta:callingRID()`. `getChannelEci` is not a shared query. The `pds` channel does not accept `clear_all_data`.
- **Signatures.** `math:hmac` was already in the math library. `math:timing_safe_equal(a, b)` compares two strings without stopping at the first different byte. `event:raw_body()` is the exact request body on a channel with `rawBody: true`. Guide: [`webhook-signatures.md`](../developing/webhook-signatures.md).
- **Public-client tokens.** Access tokens last one hour. Each refresh returns a new refresh token. Presenting a rotated refresh token again revokes that grant. A confidential app's access token still lasts 24 hours. Refresh tokens last 90 days from each successful refresh.

## Upgrade

- **`/c/` from another host, or from nginx on the same machine, now returns 401** unless the caller has a passkey session or the internal token. Set `PICO_ENGINE_ALLOW_LOCALHOST_C=1` only for a direct loopback connection with no forwarded-IP headers.
- **Install `io.picolabs.oauth` on the root** before a remote MCP client signs in. A client such as Claude needs a public HTTPS URL on port 443.
- **Existing channels are not exposed to MCP.** Open the Channels tab and allow the `channel` or `mesh` surface for each channel an agent should use. A pico ceiling from 1.8 or 1.9 does not block that; a ceiling that itself has `mcpPolicy` does.
- **`settings` no longer returns secret values.** Rulesets that read another ruleset's settings see the mask. The owner uses `pds:config_value`.
- **Public MCP clients must refresh within an hour**, and must store the new refresh token from each refresh response. Replaying the previous one signs that client out.
- **pico-framework dependents** in this repo require `^1.10.0`. Do not install the old standalone package over `packages/pico-framework`.
- Node 20 or 22. Flush `io.picolabs.pds` and `io.picolabs.pico-engine-ui` after upgrade so secret settings and the channels checkboxes match this engine.
- Docs index: `node tools/generate-llms-text.js` writes `docs/llms.txt` and `docs/llms-full.txt`.

## Not in this release

- A live pass of `/mcp/mesh/{eci}` on a Manifold mesh. Engine tests cover those tools. A Claude channel connector (`/mcp/{eci}`) was signed in and used its tools.
- An external MCP OAuth conformance tester. The engine tests cover discovery, CIMD, S256, resource binding, and scopes.
- `mesh:admin` and conversational install or child creation.
- `meta { debug on }` for unmasking a ruleset's own secrets. Logs never contain secret values.
