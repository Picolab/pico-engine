## Highlights

1. **Passkey sign-in.** WebAuthn registration and sign-in, sessions, an auth gate in the UI, and one root pico per account (multi-root, pico-framework 0.8.0).
2. **OAuth for integrators.** Client Credentials for `oauth-webhook` channels and Authorization Code + PKCE for mesh-wide integrators such as Home Assistant.
3. **The HTTP surface split.** Passkey sessions on `/c/*` (UI and internal); bearer tokens on `/sky/*` when the mesh is locked or the channel is a webhook.
4. **Channel editing** (1.5.1). Change tags and policies on an existing channel from the UI or `wrangler:updateChannel`.
5. **Invite bootstrap** (1.5.2). An invite can carry a bootstrap ruleset URL that installs on the new root when the invite is accepted.

## Why it matters

- **An engine can be put on the internet.** Before 1.5 the developer UI had no sign-in. Passkeys make a hosted engine usable without passwords.
- **The root pico is the person's agent.** One root per account was the identity decision of July 2026 that the later layers build on.
- **Integrators get scoped access.** Home Assistant became the first OAuth client of a Manifold mesh.

## Exposure before → after

| Surface | 1.4 | 1.5 |
|---|---|---|
| Developer UI and `/c/*` | Open to anyone who could reach the port | Passkey session required for external callers (localhost bypass on by default) |
| Account creation | — | Invite-gated; `PICO_ENGINE_ALLOW_SELF_SIGNUP` defaults off |
| `/sky/*` | Open | Bearer required on `oauth-webhook` channels, or mesh-wide when `io.picolabs.oauth` is installed |
| Roots per engine | One | One per account |

## Upgrade (breaking)

- A fresh engine has no root until someone registers a passkey. An existing single-root database uses a one-time "Claim with passkey."
- External callers to `/c/*` need a session. (Localhost bypass stayed on by default here; 1.10 turned it off.)
- Set `PICO_ENGINE_BASE_URL` for passkeys and OAuth redirects.
- Requires pico-framework `^0.8.0`.
